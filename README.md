# OpenFGA zone access POC

Access control for employees in a zone / area / centre / sub-centre hierarchy, with department-limited
grants and a separate salary permission, built on [OpenFGA](https://openfga.dev) v1.22.0.

Start with [docs/requirements.md](docs/requirements.md), then [docs/tech-design.md](docs/tech-design.md).
How list screens work, with pros and cons: [docs/list-queries-comparison.md](docs/list-queries-comparison.md).
What you enter for routine changes, OpenFGA versus SQL tables: [docs/change-walkthrough.md](docs/change-walkthrough.md).
What other teams report from production: [docs/research-user-experiences.md](docs/research-user-experiences.md).

## Run it

Needs Docker and Node 20 or later.

```sh
docker compose up -d            # Postgres + OpenFGA on localhost:8080
cd app
npm install
npm run setup                   # creates the store, writes the model and 68 seed tuples
npm start                       # API and UI on http://localhost:4000
```

Open http://localhost:4000, pick a persona, and compare what each one sees.

## Check it

```sh
# Model tests, no server needed (77 assertions)
docker run --rm -v "$PWD/fga:/work" openfga/cli:latest model test --tests /work/store.fga.yaml

# End-to-end scenarios against the running API
cd app && npm run scenarios
```

See the tuples OpenFGA actually stores:

```sh
docker compose exec postgres psql -U postgres \
  -c "select object_type, object_id, relation, _user, condition_name from tuple order by ulid;"
```

## Layout

| Path | What it is |
| --- | --- |
| `fga/model.fga` | The authorization model |
| `fga/store.fga.yaml` | Model tests, one block per requirement |
| `fga/tuples.json` | Seed tuples, generated by `npm run export-tuples` |
| `app/src/org.js` | Seed HR data: units, employees, grants, personas |
| `app/src/fga.js` | OpenFGA calls: Check, BatchCheck, ListObjects, ListUsers |
| `app/src/server.js` | HR API that enforces the permissions and masks salary |
| `app/public/index.html` | UI: switch persona, edit, grant, revoke, move a unit |
| `app/scripts/scenarios.js` | End-to-end scenario run |

## POC shortcuts

- No login: the caller is whatever the `X-User` header says.
- HR data lives in memory and resets on restart. Tuples persist in Postgres.
- Grant management and the salary audit endpoint are open to every persona.
- OpenFGA runs without authentication or TLS.

Re-running `npm run setup` creates a new store and points the app at it.
